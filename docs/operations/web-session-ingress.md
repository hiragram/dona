# DispatcherでのWeb session確認

`WebAuthRepository.verifySessionIngress`は、固定されたBFF contextとDispatcherの現在のsessionを照合する内部repository操作である。対象はbodyのない`GET /`と`GET /api/session`のみとする。実際のraw request target、method、bodyからroute/resource bindingを独立に導出し、BFFが署名した値と比較する。

未検証claimsのkey versionとsession refは、serverが保持する鍵と現在の行を検索するhintに限る。principal、scope、各revision/generationは監査rootと一致したDispatcher metadataから取り、10秒contextのMAC・audience・用途別鍵・期限と照合する。署名確認前のhintを監査actorへ採用せず、不正contextからsession状態を詳しく返さない。

current sessionの有効性とtoken期限を確認し、実在する暗号化payloadのbindingとdigestも同じread-only prepare内で照合する。nonceは用途を分離したSHA-256 digestだけを保存する。期限切れnonceを除いた保持数は2048件までとし、上限時は拒否する。署名token、MAC、鍵はmetadataや監査recordへ保存しない。

成功時はnonce追加とWeb metadata digestを共通監査transactionで確定し、DB外anchorのfinalizeが成功してからprincipalを返す。監査record v3は実sessionを操作対象とし、`web_auth_state`を同じsequenceのresource commitmentへ記録する。nonceの再利用は別connectionでも拒否する。途中のSQL失敗はnonce変更をrollbackし、reserve/finalizeの応答が不明なら成功を返さず自動再送しない。

既定のsession確認はidle activityを更新しない。BFFが分類したdashboardの明示navigationだけ、service署名に束縛された属性からnonce消費と同じtransactionでactivityを更新する。poll、内部再検証、scriptによるGETでは延長しない。詳細は[画面遷移のactivity](web-session-activity.md)を参照する。返すprincipalはsession確認の結果であり、job/approvalの実行権限や別transactionで使うcapabilityではない。それらは現在のresource認可とnonce消費を業務更新と同じtransactionで確定する必要がある。

BFF/Dispatcherの共有fixtureは公開の固定test keyを使う。双方のwire検証と現在のBFF署名出力のclaimsが一致することを確認し、runtimeで他packageのsourceを直接importしない。固定operation `web.session.v1`を追加するため、旧readerとのactivation/rollback compatibilityは有効化時に別途判定する。

UDS listener、peer/専用credential認証、online IdP照会、OS credential/CAS provider、browser logout/CSRF導線、runtime/readiness、backup除外への接続はまだ含まない。fixtureでの成功を実IdPやproductionの動作確認、#141全体の完了として扱わない。
